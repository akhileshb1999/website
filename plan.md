# Portfolio Website — Plan

## 1. Purpose

A personal, professional portfolio site for a research analyst. It's not a
traditional "developer portfolio" — it's a working showcase of investment
thinking: what's being tracked, the views behind it, and the person behind
the research. Tone: credible, understated, sell-side/buy-side research
aesthetic rather than flashy startup-landing-page aesthetic.

## 2. Site Structure (Tabs)

A single-page app feel with tab-based navigation (no full page reloads),
plus a landing/hero view.

| Tab | Purpose | Content shape |
|---|---|---|
| **Home** | First impression — name, role, one-line pitch, current focus, links (email, LinkedIn, Twitter/X, Substack, resume) | Hero section, short intro, CTA into other tabs |
| **About Me** | Professional background | Bio, experience timeline, education, coverage sectors, skills/tools (e.g. Excel modeling, Bloomberg, valuation methods) |
| **Coverage** | Sector → company → thesis drill-down | Three-level structure (see below) |
| **What Am I Reading** | What's being read | Books/articles/reports list, short takeaway per item, maybe tags (macro, sector, biography, etc.) |
| **What's New** | Interests beyond work / currently excited about | Short cards — hobbies, side projects, non-market curiosities, recent finds. Keeps the site human, not just a research terminal. |

### Coverage structure (drill-down)

Coverage is not a flat list — it's a three-level hierarchy:

1. **Coverage landing page** — the three sectors as top-level cards:
   **Consumer**, **Logistics**, **Capital Markets**.
2. **Sector page** — clicking a sector shows the companies followed
   within it (name, ticker, one-line current view/tag, last updated).
3. **Company page** — its own dedicated page/route with the full
   thesis: view (Bullish/Bearish/Neutral/Watching), detailed write-up,
   key catalysts/risks, conviction, valuation notes, date published/
   updated. This is effectively a mini research-note page per company.

Routing sketch: `/coverage` → `/coverage/consumer` →
`/coverage/consumer/titan`. Sectors are a fixed set of three for now,
but the model should support adding a fourth sector later without
restructuring.

## 3. Design Direction

- Clean, editorial, content-first — think a hybrid of a research note and
  a modern personal site. Generous whitespace, strong typography, minimal
  chrome.
- Light and dark mode.
- Subtle finance-adjacent visual language used sparingly: monospace
  accents for tickers/numbers, small up/down indicators for views
  (bullish/bearish), no gaudy stock-chart backgrounds.
- Fully responsive: tab bar collapses to a bottom nav or hamburger on
  mobile.
- Fast, static-first — this is a content site, not an app; should load
  instantly and work with JS disabled for core content where feasible.

## 4. Tech Stack (proposed)

- **Framework:** Next.js (App Router) + TypeScript — static export or
  ISR, good SEO, easy to host free on Vercel.
- **Styling:** Tailwind CSS.
- **Content:** MDX or JSON/YAML content files per section (e.g.
  `content/coverage/*.md`, `content/reading.json`) — no database needed.
  Editing a stock view = editing a markdown file, no CMS/backend
  required. Keeps updates fast and git-tracked.
- **Deployment:** Vercel (or GitHub Pages if a fully static export is
  preferred).
- **Icons/fonts:** system font stack or a single serif/sans pairing (e.g.
  Inter + a serif for headings) to keep it feeling like a publication.

Alternative if a simpler, zero-JS-framework approach is preferred: Astro
instead of Next.js — same content-file model, ships less JS by default.
Recommendation: **Next.js** for familiarity/ecosystem unless there's a
reason to prefer Astro.

## 5. Content Data Model (draft)

```
content/
  profile.json               # name, title, bio, links (incl. Substack), photo
  about.md                    # long-form bio / experience / education
  coverage/
    consumer/
      titan.md                 # frontmatter: company, ticker, sector, view, conviction, catalysts, date
      dmart.md
    logistics/
      blue-dart.md
    capital-markets/
      cams.md
  reading.json                # [{ title, author, status, takeaway, tags, date }]
  whats-new.json               # [{ title, description, link?, date }]
```

Sector is implicit from the folder (`consumer`, `logistics`,
`capital-markets`), so the coverage landing page and sector pages can be
generated by scanning the directory structure — adding a company is just
adding a file, adding a sector is just adding a folder.

Each `coverage/<sector>/<company>.md` frontmatter example:

```yaml
company: Titan Company
ticker: TITAN
sector: Consumer
view: Bullish        # Bullish | Bearish | Neutral | Watching
conviction: High      # High | Medium | Low
lastUpdated: 2026-07-20
catalysts:
  - Wedding-season jewellery demand
  - Margin recovery in watches segment
```
Body of the file = the full thesis write-up (markdown), rendered on the
company's dedicated page.

## 6. Build Phases

1. **Scaffold** — Next.js + TypeScript + Tailwind, base layout, tab
   navigation, routing per tab, light/dark theme toggle.
2. **Home + About Me** — static content, hero section (incl. Substack
   link), bio.
3. **Coverage** — data model, sector landing page, sector → company
   listing, dedicated company thesis page, breadcrumb navigation
   (Coverage / Sector / Company).
4. **What Am I Reading + What's New** — simpler list-based sections.
5. **Polish** — responsive QA on mobile/tablet, accessibility pass,
   meta tags/SEO, favicon, animations/transitions between tabs.
6. **Deploy** — connect to Vercel (or GH Pages), custom domain if
   available.

## 7. Suggestions

- **Substack integration beyond a link**: pull the latest 2-3 post
  titles onto Home via Substack's RSS feed, so Home shows recent writing
  without manual updates. Optional — a plain link also works fine for v1.
- **"Last updated" everywhere in Coverage**: since views change over
  time, surface the date prominently on sector listing cards and company
  pages, and consider a small changelog/history at the bottom of each
  company page (e.g. "Upgraded to Bullish — 12 Jun 2026") so the site
  reads as a living research log, not a static page.
- **Search/filter on Coverage**: once there are enough companies, a
  simple filter by sector + view (Bullish/Bearish/Neutral) on the
  landing page helps a visitor scan quickly.
- **Standard disclaimer**: a small footer note ("Views expressed are
  personal opinions, not investment advice") on every company page —
  worth having given the content is public stock opinions.
- **Resume/CV link on Home or About Me**: common expectation for this
  kind of professional site alongside Substack/LinkedIn.
- **OG/share images**: since company thesis pages are shareable
  individually (e.g. via Substack or Twitter/X), auto-generated OG image
  per company page (ticker + view) makes shared links look polished.
